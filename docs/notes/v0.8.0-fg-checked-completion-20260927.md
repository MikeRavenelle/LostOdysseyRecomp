# v0.8.0 FG checked completion：第一批实现

基线：`88b1a4b5bff98315aec8eb49f2cb3eb7527711e3`。对应交接中的P0-01/P0-03、P1保护和P4-01/P4-03的部分代码工作，不改变里程碑定义或验收状态。

## 已实现

游戏路径新增一个只记录post-present queue marker的提交/完成serial的轻量记录器。只在`vkQueueSubmit`成功后发布serial；只有匹配serial的`vkWaitForFences`成功才回收snapshot和DepthRemapper输入。失败提交、旧serial、重复完成和pending状态下的覆盖不能产生复用资格。此记录器不包含standalone probe的explicit SDK timeline模式。

`Session::Presented`对accepted Present先提交completion marker，再查询SDK状态。`GetState`失败不再绕过marker进入device-idle释放路径。`Quiesce`、resize调用边界和`Shutdown`统一先执行checked input drain；`Disable`失败以及有未决FG输入的rejected Present走明确的非零退出路径。记录/标记后缺少Present完成证据的输入不得被下一次Prepare覆盖，也不能凭device-idle释放。

`CompleteForFrameGeneration`独立检查FG的depth/motion元数据：当前帧/epoch、相机标记、深度约定、完整且匹配的零偏移区域，以及Tracked或ResetInitialization运动状态。运行时保留两张纹理，不重新要求已在producer侧验证且没有复制的color/invalidity。Composite入口及Session均使用此FG资格检查；Hybrid不再从composite路径混入FG。投影数学和原有producer/lease身份检查仍负责其各自的完整契约，元数据通过不代表实际画质或显示通过。

Composite消费端接受匹配的DLSS或FSR SR provider/consumer，不篡改原FramePlan。`CompleteForConsumer`、FSR质量档位、NativeAA、SR token和SrFailureAction原语义保持不变。FG历史在输出/输入尺寸、格式、backbuffer数量、provider变化或ResetInitialization时局部reset。

## 证据与限制

本地使用C++20、`-Wall -Wextra -Werror -pedantic`构建并运行completion-only定向测试：22项检查通过。该结果不覆盖SDK、Vulkan执行、完整Session编译、真实窗口或显示器。

新增`streamline_game_session_contract`同时覆盖completion记录器、独立FG输入资格和P1的Hybrid SR边界；复用原`temporal_frame_inputs_test.cpp`作为`streamline_sr_inputs_regression`。`FG CPU contracts`工作流在Linux/Windows运行GPU-free测试；实际CI结果以对应commit的运行记录为准。

未执行真实游戏、GPU validation、SDK sample重跑或显示取证；未访问/修改原始settings、save、profile或shader cache。GamingRig在本轮查询时离线。

- P1：仅做直接相关的输入资格保护与回归，不重开既有有界验收，也不宣称新一轮GPU/NativeAA尺寸验收。

FG继续opt-in并默认关闭。不修改发布状态、路线图完成标记或GitHub Project状态。

## 复现

```sh
cmake -S tools/tests/streamline_fg -B build/fg-contracts -DLO_STREAMLINE_FG_CPU_ONLY=ON
cmake --build build/fg-contracts --config Release
ctest --test-dir build/fg-contracts -C Release --output-on-failure
```

完成真实V0/V2验证时，应检查`submitted_input_serial`与`completed_input_serial`、retained/pending状态、事件顺序和退出码。`cleanup=complete`只表示Session本地输入清理，不能替代后续Streamline runtime/NGX清理、validation或显示侧证据。SDK内部问题继续复用原有sample归因材料。
